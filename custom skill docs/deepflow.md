# deepflow — 다각도 자문단 + 비판-개선 수렴 루프

> **용어:** "opus" = 현재 세션 적용 메인 모델(역할명, 현재 Fable 5). 정의 canonical은 agent-ops.

> 판단/추론이 무거운 질문에, 같은 질문을 N번 묻는 대신 **서로 다른 렌즈(관점)**를 병렬로 붙여 독립 의견을 모으고 opus가 **결정**까지 종합한다. 실행 메커니즘(모델 분담·idle 모델 등)은 전부 **agent-ops**를 따름.

## 언제 켜나
- 트리거: "자문단", "여러 관점에서", "다각도로 봐줘", "패널 붙여줘", "council", "/deepflow". opus가 다각도 판단이 필요하다고 보면 명시 요청 없이 자가 활성 가능.
- **켜는 조건:** 추론/판단이 중요하고 **여러 각도가 결론을 실제로 바꿀 때만.**
- **건너뛰기:** 사실 조회 / 계산 / 검색 / 단일정답 기술 결정 → 직접 답하고 "패널 불필요"라고 말함.

> ⚠️ 렌즈는 같은 모델(sonnet) → **인식론적으로 독립 아님**(블라인드스팟 공유). 가치는 *강제된 프레이밍 분리*지 통계적 다양성이 아님. **합의를 진실로 읽지 마라**(→ §5 교차점검).

## §0 활성화
- 명시(`/deepflow`, "자문단", "다각도로") → 활성. 암묵적이지만 적합 → opus 자가활성: 한 줄("다각도 사안 같으니 패널 돌립니다 — 질문 몇 개 먼저") 후 바로 §1로.
- **컴포넌트 모드(외부 호출):** 부모(예: buildflow)가 결정문/기준/제약을 이미 공급하면 §0–§1 건너뛰고 **§2부터 진입** — 호출자의 게이트(buildflow G1/G2)가 대체, 6필드 반환이 그 게이트에 피드.

## §1 20문답 (opus 직접)
패널 품질 = 결정문·기준·사실의 품질. 얇은 입력 → 렌즈가 추측으로 채움 → 그럴듯한 쓰레기. 그러니 사용자를 먼저 캔다.
- **탐침(우선순위):** 진짜 결정(표면 질문 뒤) · 기준 + 가중치 · 제약 · 결정적 사실 · 숨은 선호/딜브레이커 · 이해관계자 · 성공/악몽 시나리오.
- **방법:** AskUserQuestion, **묶어서**(2~4개씩), **적응적**(불확실한 것만 후속), 최대 1~2라운드. 날카로운 결정문 + 기준 + 제약을 쓸 수 있게 되는 순간 중단.
- **탈출 게이트:** 사용자가 "그냥 결정해" 하면 **명시된** 가정으로 빈칸 채우고 진행.

출력 = 한 줄 **결정문** + 가중 기준 + 핵심 제약/사실.

## §2 렌즈 구성 (동적)
고정 풀에서 고르지 않는다. **opus가 이 작업 도메인에 맞는 렌즈를 구성** — 결론을 실제로 바꿀 수 있는 각도. 이 도메인 *안에서* 다양성 추구(보여주기용 무관 도메인 렌즈로 채우지 말 것).
- **개수:** opus가 여전히 날카롭게 종합할 수 있는 만큼 — 3~5개 시작, 도메인 넓으면 더.
- **각 렌즈 = 날카로운 지시 하나**(페르소나 롤플레이 아님). 영감용: 낙관(상방, 왜 되는지) / 사전부검("이미 실패했다", 역추적) / 증거·기저율 / 제1원리 / 대안 / 장기·2차효과. **고정 메뉴 아님.** 도메인에 가치/윤리/법/감정 축이 있으면 그걸 구성; 순수 기술 작업엔 안 함.
- **직교성 & 커버리지 점검(sonnet, work 티어):** 초안 렌즈셋을 sonnet 1개에 넘겨 — (㉠) 렌즈들이 정말 다른 각도인가(중복/같은축 양극 없나)? (㉡) 결론 바꿀 축이 빠졌나? opus가 피드백 접고 확정.

## §3 병렬 렌즈 에이전트 (sonnet, lens 티어)
렌즈당 sonnet 1개, 한 메시지에 다 발사(독립). 모든 렌즈 프롬프트에 `ultrathink`(프롬프트가 유일한 추론 레버).
- **출력 = agent-ops Report 봉투, lens 티어 페이로드** — 고정 6필드: `stance · reasons · killer_point · risks · flip_condition · confidence`. 각 reason에 `[fact-cited|inference|assumption|base-rate]` 태그; 인용/숫자/인과사슬 verbatim 보존(flip_condition 판단에 필요).
- 프롬프트 핵심: "[렌즈]로만 평가; 중립으로 후퇴 금지 — 당신의 가치는 한 방향으로 날카로운 것, 균형은 다른 렌즈 몫; 다른 패널 못 봄; 증거 vs 추측 태그." 고정 필드 순서가 패널을 비교 가능하게(stance-vs-stance, killer-vs-killer).

## §4 라운드 2 (적응적)
교차반박 라운드는 ANY 성립 시: 핵심 분열이 **사실 다툼**(한쪽이 틀렸을 수) · 격차가 결정을 **바꿀 만큼 큼** · 한 에이전트가 다른 이들이 답해야 할 **killer**를 던짐. 대체로 합의거나 격차가 취향/우선순위면 건너뜀(트레이드오프로 보존).
- 라운드 2 = sonnet + `ultrathink`, **다이제스트만**(각 stance + killer_point) 피드, `concessions / rebuttals / changed_mind / final_stance / confidence` 반환.
- **loop-until-dry(선택 철저 모드, = Workflow `loop-until-dry`):** **연속 2회 dry**(새 의미 있는 비판 0)까지 반복; 적대자에게 "매 라운드 새 약점만". 하드 라운드 캡(기본 5) — 캡인데 실제 이슈 계속 나오면 비수렴 = 사용자 에스컬레이트(강제 통과 없음).
- **meaningful 비판** = 새롭고 + 실질적 + 실행가능 + 결론을 바꿈. 반복/트집/스타일/범위밖/과설계는 아님.
- **사실 다툼 해소:** 다툼 사실은 **도구**로 확인(WebSearch/측정/코드실행); 확인 불가면 "미확인 사실다툼" 표시 + 그에 기댄 결론 신뢰도 **낮춤** — opus 사견으로 정리 금지(그러면 라운드 2 무효).

## §5 종합 (opus 직접)
```
consensus : 대다수/전부 동의 = 약한 신호(같은 모델/공유 입력일 수) → 증거·기저율 대조해 단단히
conflict  : 분열점 + [사실 다툼 vs 가치/우선순위 다툼]
blind spot: 아무도 안 건드린 것(opus 메타점검 + §2 직교성 sonnet이 먼저 잡음)
```
**flip_condition 점검(§6 전):** 모든 렌즈의 flip_condition 모아 confirmed / unconfirmed / unconfirmable 분류. **미확인이지만 결정 바꾸는** 것 → 도구로 확인하거나 추천 신뢰도 낮춤/에스컬레이트. (모아놓고 무시 금지.)

## §6 결정 (opus 직접 — 추천 + 소수의견)
기준으로 가중, 하나의 추천으로 수렴. 형식: **결정문** · **추천** + 한 줄 이유 · 렌즈별 핵심(1~2줄) · 합의↔갈등(사실 vs 가치) · **소수의견**(반대 렌즈 주장, 깎지 않고 보존) · flip 조건 + 신뢰도(高/中/低).
- **opus 자가채점 편향:** opus가 *자기* 제안을 패널로 판단할 때(예: buildflow B모드) 수렴 욕심에 유효 비판을 "무의미"로 깎는 경향 → 진행/정지 판단은 **반증 가능한 dryness**(연속 2회 0-new)에 근거, 느낌 아님; 적대 강도를 끝까지 유지.
- **★ 사용자의 명시적 기획을 납작하게 만들지 마라(user directive, 2026-06-28).** 패널이 제약(좁은 뷰포트·비용·성능)에 맞춰 최적화한 결론이 사용자가 명시한 것(그들의 UI·플로우·구조)을 *대체*할 때, "최적화된" 버전으로 종합해 사용자를 설득하지 마라. 충돌은 **사용자가 결정할 트레이드오프**로 드러내되, 사용자 원안을 **동등한(더 약하지 않은) 선택지**로 제시 — 패널은 사용자 비전을 단단하게 하지 뒤엎지 않는다. 또: **사용자가 의도적으로 둔 제약을 거꾸로 뒤집지 마라.** (실측: 디자이너 패널이 사용자의 Claude식 *플로팅* 드로어를 "320px에선 오버레이가 어차피 80% 덮음"으로 풀스크린 레이아웃으로 갈아치웠고, opus가 그쪽으로 설득해 사용자 승인 후 전부 되돌리며 패널이 기획을 "납작하게 만들었다"고 함. 사용자는 패널이 좁아서 드로어를 선택전용으로 둔 것 — 작은 플로팅 패널이 의도였지 "풀스크린은 불가피"가 아니었다.)

## 모델 분담 & 실행
> 실행 메커니즘(Agent-vs-Workflow, 모델별 함정, fire→signal→resume "idle" 모델, opt-in)은 **agent-ops가 canonical**. 아래는 deepflow 고유 단계 매핑만.
- **sonnet**(`ultrathink`): 직교성 점검(§2), 렌즈 의견(§3), 라운드 2(§4). **opus:** 활성(§0), 20문답(§1), 렌즈 구성/확정(§2), 종합(§5), 결정(§6).
- **단계→기반 매핑:** §0–§1, §5–§6(load-bearing) = opus 직접. §3–§4 = **백그라운드 `Workflow`**(렌즈 팬아웃은 패널, 절대 opus 막는 포그라운드 병렬 Agent 아님 — agent-ops idle 모델): §3 = `parallel`+`schema`, §4 = `loop-until-dry`. opus는 완료신호마다 라운드별 재활성(종합). 모든 렌즈/라운드2 `agent()`에 `model:'sonnet'`. buildflow 컴포넌트로 쓰일 땐 buildflow의 Workflow 스크립트 안에서 돈다(중첩 아님).

## §7 deepflow-auto — 비판→개선 수렴 루프 (확장 모드)
기본 deepflow는 **결정**에서 멈춘다. deepflow-auto는 계속 간다: **비판 → opus 종합 → 개선(실행) → 재비판**을 *산출물 자체*가 수렴할 때까지 반복. 도메인 무관 — 개선 가능한 모든 산출물(문서·코드·디자인·계획). (멀티사이클 hwpx 보고서 개편에서 입증: 구조→스타일→내용→양식준수, 매 라운드 패널 + 범위 한정 재작성.)

**활성:** 명시("deepflow-auto", "검사 및 개선 사이클", "비판-개선 반복", "수렴까지"). opus가 *제안*은 가능하나 **자동 실행은 opt-in**(라운드마다 다수 에이전트 — agent-ops Workflow와 같은 게이트).

**루프 (라운드 R):**
- **0. 타깃 추출** — 산출물을 비판 가능한 텍스트로(문서→레벨/구조 마커 단 본문 추출; 코드→diff/파일). **매 라운드 재추출** — 직전 라운드 후 (특히 *사용자가*) 편집했으면 그 편집이 새 베이스(canonical-check; 낡은 복사본 비판 금지).
- **1. 비판 패널(§2–§3)** — 도메인 적합 렌즈 병렬(sonnet, `ultrathink`, Report 봉투, lens 6필드). **"이미 고침 — 재플래그 금지" 컨텍스트 전달**해 해소된 이슈 재론 방지(dryness가 여기 의존).
- **2. opus 종합(§5) — load-bearing, 위임 안 함.** opus가 각 비판을 **원자료에 대조해**(논문/스펙/요구사항/사용자 의도) 판단, 비판 텍스트만 보고가 아님. 출처별 채택/기각; 렌즈 간 합의 = 약한 신호(같은 모델). 이 라운드 수정 **범위** 결정.
- **3. 개선(실행)** — 채택 지시를 **섹션/청크 단위 sonnet 작성자**에게(Workflow, `model:'sonnet'`, **파일로 쓰고 경로+통계만 반환** — agent-ops 고출력 규칙; 본문 재방출 금지). **명명된 섹션으로 범위 한정** — 전체 재작성은 churn하고 회귀; 이 라운드 채택분만 건드림. 안 바뀐 섹션은 복사 전진, 재생성 안 함.
- **4. 재비판 → loop-until-dry(§4)** — 개선본 재추출, 1단계로. **연속 2라운드 *의미 있는* 비판 0 = 수렴 → 정지.** 라운드 캡(기본 5); 캡인데 실제 이슈 남으면 **사용자 에스컬레이트**(강제 통과 없음).
- **5. 라운드별 보고** — 사용자가 읽는 산출물이면 라운드별 짧은 변경 요약(무엇을 왜 채택/기각).

**규율:**
- **opus** = 종합 · 출처 대조 채택/기각 · 범위 결정 · 수렴 판단. **sonnet** = 비판 렌즈 + 개선 실행. (opus는 판단자로 남고 sonnet이 양을 친다.)
- **범위 한정 섹션만 개선.** 1순위 실패 모드는 선의의 전체 재작성이 고친 문제를 재도입하는 것 — 매 라운드 좁게.
- **매 라운드 canonical 재추출.** 사용자가 라운드 사이 손편집할 수 있음; 그걸 조용히 덮으면 전체 취지 무효.
- **자료 기반 판단.** 비판은 *단서*지 판정이 아님 — 채택 전 출처 대조(날카로워 보이는 렌즈도 틀릴 수, opus가 판단 소유).
- Workflow 백그라운드 · opt-in · 티어별 모델(agent-ops). 문서는 `new-hwpx-master`와 페어(styleIDRef 레벨 스타일, 텍스트 구분자 없음).
