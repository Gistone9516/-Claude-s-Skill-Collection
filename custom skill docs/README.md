# 커스텀 오케스트레이션 스킬 사용법

직접 만든 오케스트레이션 스킬 3종의 사용 가이드. opus(나, 운영자)가 sonnet 에이전트들에게 일을 어떻게 나눠 맡길지에 대한 규칙 모음이다.

## 한눈에 보기

| 스킬 | 한 줄 정의 | 언제 쓰나 |
|---|---|---|
| **agent-ops** | opus↔sonnet 분담·팬아웃·위임 절차의 **단일 출처(SoT)** | 에이전트를 띄우기 **직전**. 모든 위임의 기본 규칙 |
| **buildflow** | 기획→설계(계약)→병렬구현 멀티사이클 워크플로 | 기능을 **여러 폴더에 걸쳐 구현**할 때 (바이브코딩) |
| **deepflow** | 다각도 자문단 + 비판→개선 수렴 루프 | **판단·결정**이 다각도로 갈리는 질문, 산출물 반복 개선 |

## 핵심 구조 — 셋의 관계

```
        agent-ops  ← 실행 메커니즘의 SoT (모델 분담·Workflow·Report 봉투·팬아웃 캡)
        ▲       ▲
        │ 호출   │ 호출
   buildflow   deepflow
        │
        └─ 자문단/비판 단계는 deepflow를 컴포넌트로 호출
```

- **agent-ops**는 "어떻게 위임하는가"의 규칙집이다. 다른 두 스킬은 이걸 *참조*만 하고 다시 적지 않는다. **충돌 시 agent-ops가 이긴다.**
- **buildflow**는 구현 워크플로. 그 안의 적대적 검토 단계는 **deepflow**를, 위임/모델 규율은 **agent-ops**를 불러 쓴다.
- **deepflow**는 판단용 패널. 실행 메커니즘(모델 분담·idle 모델 등)은 전부 **agent-ops**를 따른다.
- 셋 모두의 실행 기반은 빌트인 **`Workflow` 도구**다(스킬이 아님). 멀티에이전트 작업은 이 도구로 백그라운드 실행한다.

## 어떤 걸 골라야 하나 (의사결정)

```
질문이 "사실 조회·계산·단일정답"인가?
  → 예: 어떤 스킬도 필요 없음. 바로 답한다.
  → 아니오 ↓

작업이 "코드/기능을 여러 폴더에 구현"인가?
  → 예: buildflow
  → 아니오 ↓

"판단·결정이 다각도로 갈리는가" 또는 "산출물을 수렴까지 반복 개선"인가?
  → 예: deepflow (후자는 deepflow-auto)
  → 아니오 ↓

그냥 탐색·조사·실행을 sonnet에 나눠 맡기는 일인가?
  → 예: agent-ops 만으로 충분 (에이전트 직접 위임)
```

## 공통 전제 (셋 다 적용)

- **opus = 병목이자 최고가치 판단자.** 읽기·탐색·1차작업·서베이는 전부 sonnet으로 내린다. opus는 판단·구성·결정·"보는 일"만.
- **멀티에이전트는 opt-in.** "ultracode", ultracode-on 세션, 또는 명시적 "워크플로 써/팬아웃해/오케스트레이션해"가 있을 때만 `Workflow`를 띄운다. 아니면 제안 + 대략 비용만 알리고 자동 실행 금지.
- **쓰기는 직렬, 읽기/탐색만 병렬.** 동시 편집은 파일을 깨뜨린다. 병렬 쓰기는 폴더별 git worktree로 격리.
- **근거 기반 — 임베딩 단정 금지.** 사실/버전/가격/API/실현가능성 주장은 웹검색 등 도구로 근거를 잡는다. 위임받는 에이전트에게도 동일하게 지시.

## 자동 동기화 (스킬 변경 → 문서 갱신)

SKILL.md를 고치면 이 문서들도 따라 갱신되도록 훅을 걸어 뒀다. 문서 재작성은 LLM(Claude) 작업이라 셸 훅이 직접 못 하므로, 훅은 **"스킬이 문서보다 최신"임을 감지해 Claude에게 갱신을 지시**하는 방식이다.

- **감지 스크립트:** `sync-check.ps1` — 각 SKILL.md mtime을 대응 문서(`<name>.md`) mtime과 비교, 더 최신이면 갱신 지시 JSON(`additionalContext`)을 출력. ASCII 메시지(PowerShell 5.1 cp949 한글 깨짐 회피). 에러는 조용히 무시(세션 안 막음).
- **훅 위치:** `~/.claude/settings.json`
  - `SessionStart` — 세션 시작마다 검사(에디터로 직접 편집한 것까지 포착).
  - `PostToolUse` (`Write|Edit`) — 세션 중 스킬을 고치면 즉시 검사.
- **동작:** stale 감지 → Claude 컨텍스트에 "해당 `<name>.md`를 SKILL.md에 맞춰 갱신하라(먼저 Read 대조, 사용자 확인)" 주입 → Claude가 갱신.
- **대상 매핑:** `agent-ops`·`buildflow`·`deepflow` (스킬 추가 시 `sync-check.ps1`의 `$skills` 배열에 이름 추가).
- **주의:** 훅을 세션 도중 추가했으면 이번 세션엔 `/hooks`를 한 번 열거나 재시작해야 활성화됨. 다음 세션부터는 자동.
