# buildflow — 기획→설계→병렬구현 멀티사이클 워크플로

> **용어:** "opus"/"운영자 opus" = 현재 세션 적용 메인 모델(역할명, 현재 Fable 5). 정의 canonical은 agent-ops.

> 기능을 **여러 폴더에 걸쳐 구현**할 때(바이브코딩). 단일파일 편집·한 줄 버그·순수 탐색에는 쓰지 않는다(그건 agent-ops/deepflow 직접). 적대적 자문단 = **deepflow**, 위임/모델 규율 = **agent-ops** — 둘 다 컴포넌트로 호출.

## 언제 켜나
- 트리거: "기능 구현해줘", "바이브코딩", "기획-설계-구현", "spec-driven 병렬 구현", "buildflow".
- **전제:** git 저장소가 있어야 함(사이클 경계·롤백·머지·스펙드리프트 게이트가 전부 git 기반). 저장소 아니면 `git init` 먼저 제안.

## 역할 정의
- **운영자 opus:** 기획·설계·스펙·통합·판단·게이트.
- **구현자 sonnet:** 적대적 렌즈·병렬 구현·검증.

## 4대 원칙
1. **맞춤 > 예측** — 완벽히 캐묻지 말고, 싼 구체물(스펙/슬라이스)을 빨리 보여주고 반응으로 교정.
2. **정합 삼각대** — 사용자 의도(수직) + 적대 에이전트 무결성(수평) + 얇은 슬라이스 현실점검. 셋 다 통과한 스펙만 병렬 빌드로.
3. **무한 방지** — 끝없는 20문답/리뷰 금지; 게이트와 dry-수렴으로 닫는다.
4. **양 ≠ 검증** — "N개 에이전트가 봤다"가 견고함은 아니다; opus가 에이전트 출력을 타깃에 대조해 게이트.

## 마스터 흐름 (N 사이클)
```
진입 → [기획 모드 A/B]
 ① plan  의도 + 분할맵(폴더 분할 / 스펙파일 ≤~400줄·5k) ──G1→
 ② spec  폴더별 계약(타입시그·스키마·에러규칙) + 적대 무결성 검토 + 사용자 빨간펜 ──G2→
 ③ build  폴더 = git worktree = sonnet 1 (담당 전체 읽기 → 얇은 슬라이스 먼저 → 통합·머지·테스트 = opus)
 ④ close  회귀+신규 검증 · 스펙↔코드 재동기화 (git 게이트)
 ⑤ 다음 사이클? → [사이클 기준 분류]
 지속 상태: 분할맵 · .md 계약 · 코드 · 테스트 · 디버그 인덱스
```

## 단계별

### ① Plan (WHAT/WHY + 뼈대) — 최상류 SPOF
잘못된 계획은 스펙+빌드를 ×N 버린다. 레버리지 최고.
- **opus:** 의도용 유한 20문답(계약 초안을 쓸 수 있게 되면 중단) + **분할 설계**(폴더 분할 + 스펙파일 인벤토리, 각 ≤ ~400줄/5k — 에이전트가 스펙 전체를 한 번에 참조할 수 있는 크기).
- **sonnet 적대 렌즈(deepflow):** 판정이 아니라 **"사용자에게 물을 질문 · 숨은 가정 · 놓친 대안"** → 20문답을 압축.
- **G1:** 의도 + 분할맵을 사용자가 비준(A모드) 또는 B모드 루프로.

### ② Design·spec (HOW = 계약) — 빌드 SPOF
- **opus — SoT 우선(폴더별 계약보다 공유 인터페이스 먼저).** 계약들이 교차 인터페이스(공유 타입·필드명·enum·에러코드·**직렬화 스키마**·**런타임 배선**)를 공유하면, opus가 **하나의 공유 인터페이스 SoT(`_인터페이스계약.md`)를 먼저** 쓰고, 폴더별 계약을 그것에 맞춰 초안한다(SoT가 권위 — "충돌 시 SoT 승"). 독립 초안 후 화해 = N라운드 churn(관측: 6계약 스펙에서 **7라운드**).
- **opus:** 폴더별 스펙을 지속 `.md` 계약으로 — *기계검증 가능한* 인터페이스(타입시그·데이터스키마·에러규칙), 산문 아님. ~400줄/5k 초과 = 쪼개라는 신호.
- **sonnet 적대 무결성 검토(deepflow, 수평):** 미정의 계약·놓친 엣지·내부모순·과스펙. opus가 트집/과스펙 잘라냄.
- **사용자 빨간펜(수직, 의도):** 스펙 `.md`를 직접 검토.
- **G2:** 빨간펜(의도) + 적대(무결성) 통과.
- **화해 게이트(무한 방지):** 다중계약 정합 점검 시 각 잔여 이슈를 **BLOCKING**(SoT가 못 푸는 실제 교차 깨짐 — 타입/필드/시그니처/누락함수) vs **NON_BLOCKING**(SoT가 이미 덮은 국소 표현)으로 분류. **BLOCKING=0**에서 수렴 — SoT가 덮은 표면 트집은 쫓지 않는다.

### ③ Build (1순위 가치: 시간)
- **opus:** 파티션으로 분해 → **폴더 = git worktree = sonnet 1** 병렬(캡 = agent-ops). 각 sonnet은 **자기 worktree만** 편집; **공유파일(타입/설정) + 최종 머지 = opus**(CLAUDE.md "쓰기 직렬"의 명시적 worktree 예외). 머지 충돌은 opus가 해결.
- **병렬 빌드 = 진짜 독립 파티션만**(agent-ops 독립성 규칙). 생산자→소비자는 절대 동시 병렬 금지 — 파이프라인하거나 공유입력을 미리 준비(관측: 동시 병렬 시 소비자가 가짜 대체 입력을 지어내 opus 머지를 강제함).
- **sonnet 하드룰:** 시작 전 **담당 전체(자기 스펙 + 폴더 내 관련/기존 파일)를 누락 0으로** 읽고 커버리지 자가보고.
- **얇은 슬라이스 먼저(현실점검):** 파티션 하나 빌드 → 사용자 반응 → 계약 OK → *그 다음* 나머지 팬아웃.
- **통합·머지·통합테스트·정밀편집·로직 = opus**(위임 안 함).

## 사이클 (N)
- **지속 상태:** 분할맵 · `.md` 계약 · 코드 · 테스트 · 디버그 인덱스.
- **진입 시 폭발반경:** 가산적(새 폴더) / 내부(폴더 안) / 계약 변경(교차폴더, 전파).
- **회귀 방어:** 전체읽기+검증을 *기존* 코드까지 확장; close 검증 = 신규 + 회귀.
- **close = 스펙↔코드 재동기화** → 구조적으로 스펙 드리프트 차단.
  - **git 게이트(자동감지):** 사이클 close = 커밋 + 태그. 스펙 `.md`와 건드린 코드가 **같은 커밋 범위**에 들어갔는지 `git`으로 점검 → 코드만 바뀌고 스펙은 안 바뀐 폴더가 있으면 **다음 사이클 G1 차단**(재동기화 강제). 선언이 아니라 검증 가능한 게이트.
  - **롤백** = 사이클 태그로 `git revert`/reset.

## 사이클 기준 분류 (자율성)
```
opus 1차 판정
 ├ [major] → 사용자(필수): 의도/범위 변경 · 교차폴더 public 계약 변경 ·
 │           되돌릴 수 없음/외부(데이터·스키마·인증·결제·API·배포) · 진짜 모호
 └ [minor] (가산·내부·버그·계약이행) → sonnet×3 적대 점검(㉠계약·전파 ㉡회귀 ㉢의도·범위)
       ├ 플래그 0 → 자동 진행
       └ 플래그 → opus 재검토/재분류 → 오탐 해소 → 자동 + FYI · 진짜/불확실 → 사용자(필수)
```
비대칭 위험: 놓친 major ≫ 불필요한 점검 → 애매하면 사용자 쪽으로.

## 기획 모드 A / B
- **A (기본):** 기획은 항상 사용자 검토.
- **B (명시 부여 시):** opus 계획 → sonnet×3 적대 → opus 재판정 ⟲ **연속 2회 dry(새로운 의미 0)까지** → 설계. 적대자: "매 라운드 새 약점만, 계획을 반박하라." 하드 라운드 캡(기본 5) — 캡에서 실제 이슈가 계속 나오면 비수렴 → 사용자.
  - **B 자율 천장 = 도출 가능한 개선**(버그·완성·하드닝·기술부채·백로그). *새 의도/방향*이나 *기존 계획 변경*은 사용자. 자율 기획/수렴은 FYI 로그(자가채점 편향 방지).
  - **B = 사이클 전체에 걸친 연속 자율**, 기획만이 아님: 분류-major가 없으면 ②→③→④→다음 사이클을 자율 실행. 단계 게이트마다 멈춰 routine 승인 받지 않음.
  - **실행 = Workflow 오프로드**(agent-ops, opt-in): 적대 수렴 루프, ③ worktree 팬아웃, ④ 검증을 `Workflow` 스크립트로 → 짧은 opus 턴. opus는 ② 계약 확정, 통합/머지, 위험쓰기, 분류 유지.
  - **무인(자리 비움):** 원하면 `CronCreate`/`ScheduleWakeup`로 깨워 → 다음 Workflow 단계 실행 → major/하드플로어만 에스컬레이트. 비용 절감 아님(캐시-콜드), 무인 지속용.
  - **비차단 자율(park-and-continue) — 완전위임 런:** 큰 범위를 무인 완료하도록 권한 받으면 결정마다 멈추지 않는다:
    1. **근거로 먼저 해소.** 불확실은 멀티에이전트 웹검색 검증(병렬 sonnet, 웹근거) 시도. 풀리면 해소 + FYI 로그.
    2. **막지 말고 주차.** 진짜 사용자가 필요하면(취향·모호 의도·되돌릴 수 없음/외부) 실행 결정 로그 파일(예: `_사용자판단대기.md`)에 추가하고 **그 부분만 건너뛰고 같은 작업의 나머지를 계속.** 되돌릴 수 없는/외부 동작은 절대 자동 실행 금지 — 주차 = 안전하게 안 하고 기록.
    3. **종료 브리핑.** 범위 작업 다 끝나면 주차된 결정 전부를 한 브리핑 문서로(맥락·옵션·추천).
    - 하드플로어 실패(테스트/통합 실패, 손상)는 여전히 **정지** — 깨진 위에 못 짓는다. 주차는 *결정*에만, *깨진 상태*에는 아님.

## 교차 규칙
- **하드 플로어(모든 클래스/모드):** 회귀/통합 테스트 실패 → 정지 & 보고 · 되돌릴 수 없음/외부/보안 → 항상 사용자 · 스펙 재동기화 항상 · 자동 사이클 누적 시 주기적 요약.
- **적용성:** *독립 분해 가능한* 작업만 병렬화(N개 CRUD · 테스트 · 보일러플레이트 · 동형 마이그레이션 · 다중 컴포넌트). 고결합 → 직렬(Amdahl). 기본 반사로 깔지 말 것.
- **디버그 인덱스:** 에러 → opus가 스펙으로 파티션 위치 특정 → 그 worktree의 sonnet 재발사. (파티션 *내부* 버그엔 강함; *경계* 버그는 계약이 경계를 명시해야 작동 → 그래서 ②의 계약은 기계검증 가능해야 함.)

## 컴포넌트 구성
- **적대 자문단 = `deepflow`(컴포넌트 모드):** buildflow가 결정/기준/제약을 공급하므로 deepflow는 §0–§1을 건너뛰고 §2에서 진입(G1/G2가 대체), 반환이 게이트에 피드. 쓰임: ① 계획 질문, ② 스펙 무결성 검토, B모드 적대 루프, 분류의 sonnet×3.
- **위임/모델 규율 = `agent-ops`**(model=sonnet · ultrathink · caveman · Report 봉투 · 전체읽기 · 폴더=git worktree · 통합=opus · 티어 캡 work/verify/lens). 적대/렌즈 = **lens 티어**.
- **자율 엔진 = `Workflow` 도구**(메커니즘은 agent-ops "Workflow 오프로드"가 canonical, fire→완료신호→resume "idle" 모델 포함). B모드/멀티사이클 비용 레버 — loop-until-dry(수렴) · pipeline(③ 빌드 · ④ 검증). **opt-in 필수; ⚠️ 모든 `agent()`에 `model:'sonnet'`**(load-bearing은 스크립트 밖 opus).
- 에이전트 출력은 **agent-ops Report 봉투**를 따름.

## 체크리스트
| # | 점검 |
|---|---|
| ① | 모드(A/B) → 의도 + 분할맵(폴더 / 스펙 ≤5k) → G1 |
| ② | 폴더별 기계검증 가능 계약 → 적대 무결성 + 빨간펜 → G2 |
| ③ | 폴더=git worktree=sonnet, 전체읽기/커버리지 → 슬라이스 먼저 → opus 통합 (opt-in 시 Workflow, `model:'sonnet'`) |
| ④ | close: 회귀+신규 검증 + 스펙↔코드 재동기화(git 게이트) |
| ⑤ | 분류 → 다음 사이클 자동/사용자 |
