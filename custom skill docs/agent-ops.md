# agent-ops — 위임/실행 메커니즘

> **용어 (사용자 지시, 2026-06-10):** 이 문서·스킬들의 "opus" = **현재 Claude Code 세션에 적용된 메인 모델**을 뜻하는 역할명(현재 Fable 5)이지 고정 모델 `claude-opus-*`가 아님. 세션 모델을 바꾸면 모든 "opus"가 따라간다. 워커 티어 "sonnet"은 문자 그대로 sonnet.

> **이게 SoT다.** opus↔sonnet 분담, Workflow 오프로드, Report 봉투, 팬아웃 캡 — 위임의 모든 규칙이 여기 산다. buildflow·deepflow는 이걸 참조만 한다. 에이전트를 띄우기 **직전에** 로드.

## 언제 켜나
- 트리거: "delegate", "fan out", "spawn agents", "use subagents", "에이전트 분담", "팬아웃", "위임" — 또는 opus가 일을 에이전트에 넘기려는 모든 순간.
- 핵심 반사신경(opus 아끼기 / sonnet=수집·탐색·실행·검증, opus=판단·구성·결정·보기 / 쓰기 직렬 / 사소한 1회성은 위임 안 함)은 전역 CLAUDE.md에 상시 켜져 있음. 이 스킬은 그 위에 절차를 더한다.

## 핵심 전략 — opus는 예산이 아니라 병목
- **목표 = 시간 + 품질** (비용 아님). sonnet은 풍부하니 무거운 읽기/탐색/1차작업/서베이를 다 내려서 **원문이 opus 컨텍스트에 안 들어오게** 한다.
- **opus 전용 (위임 불가):** 배포 계획 · 결정적 종합 · 승인/되묻기 · 위험 쓰기 결정 · 산문 작성 · "봐야 아는" 판단. 그 외 "읽고 정리"는 전부 sonnet.

## 추론 깊이 게이트 — opus 비용 1순위 레버
- opus 비용은 **출력**(사고 + 표시 텍스트, 입력의 ~5배) + **매 턴 다시 읽는 캐시 컨텍스트**가 지배한다. 긴 opus 턴은 둘 다 부풀린다.
- 따라서 **추론/출력 길이가 병목이지 에이전트 수가 아니다.** 사고 깊이를 사안의 무게에 맞춰라.
- Report의 **ROUTE 토큰**으로 강제: 결과가 돌아오면 ROUTE를 **반사적으로 따르고 재숙고하지 않는다.** "더 깊이 읽을까?"를 추론하는 것 자체가 비용 — 에이전트가 ROUTE에 미리 인코딩해 둔다.

## Workflow 오프로드 — 구조적 비용 레버 ★
> **강한 규칙(사용자 기본값):** 멀티에이전트 작업은 **백그라운드 `Workflow`**로 돌리고, **opus는 완료될 때까지 유휴(idle)** 상태로 둔 뒤 최종 구조화 결과만 읽는다. 다단계/멀티에이전트/구현 작업을 **포그라운드 병렬 `Agent` 팬아웃으로 막지 마라** — opus가 내내 켜져 컨텍스트를 태운다.

- **"유휴(idle)"의 정확한 뜻:** opus가 에이전트를 백그라운드 Workflow로 *발사* → **opus 턴이 끝난다** → Workflow 완료 신호에만 재활성 → 결정적 부분(종합/검증/커밋) 수행 → 다음 Workflow 발사 → 다시 턴 종료. 비판/렌즈 **패널조차** 백그라운드 Workflow로 넣는다(포그라운드 팬아웃 금지).
- **⚠️ 티어별로 모델을 지정하라 — Workflow 1순위 함정.** `Workflow`의 `agent()`는 **세션 모델(=opus)이 기본값**이다(`Agent` 도구와 다름). 절대 기본값에 의존하지 말고 **모든 `agent()`에 `model:'sonnet'`**(work/verify/lens 티어). 빠뜨리면 오프로드 전체가 조용히 opus로 돈다.
  - 파이프라인 단계는 검토 없이 자동 전파되므로, 결정적 중간 단계는 opus로 빼거나 sonnet 적대검증 단계를 덧붙인다.
- **Agent vs Workflow:** 1회성 위임 1~2개 → `Agent`(한 메시지에 병렬). 다단계/루프/에이전트 ~6개 초과 → `Workflow`. 루프·파이프라인이 되는 순간 Workflow 기본.
- **Cron/ScheduleWakeup ≠ 비용 절감.** 컨텍스트 리셋을 가로질러 **무인 진행**용. 5분 캐시 TTL 넘긴 깨우기는 캐시-콜드라 더 비싸다.

## 에이전트 띄우기 (`Agent` 도구)
- **모델 = sonnet (haiku 금지).** `model:'sonnet'` 설정. 복잡한 설계/미묘한 판단/최종 종합만 opus.
- **추론은 프롬프트로 올린다** — `think hard`, 추론 무거우면 `ultrathink`. (effort 파라미터 없음, 프롬프트가 레버.)
- **출력 스타일 = caveman-ultra** (프롬프트에 지시): 열거/데이터는 초압축, 판단·주의·VERBATIM 블록은 절대 압축 금지(Report 봉투 규칙).
- **근거 기반 (사실/조사/실현가능성 작업은 필수).** "임베딩 말고 웹검색으로 근거 잡아라"고 지시. Report에서 `[fact-cited]`는 **실제 출처**(URL/파일/실행결과)만. 근거 없는 주장은 `[assumption]` + 신뢰도 낮춤.

### 고출력 작업 — 에이전트 최대로, 단일샷 금지 (★32k 출력 캡)
- 에이전트 1개 응답은 **32,000 출력 토큰 하드캡**. 넘으면 아무것도 못 받고 실패한다.
- 긴 파일 쓰기/번역/문서생성/전체편집 등은 **자연 단위(섹션/챕터/파일/청크)로 쪼개** 각 출력이 32k 한참 아래(~8~10k 목표)가 되게 팬아웃.
- **각 에이전트는 자기 청크를 파일로 직접 Write하고 경로+통계만 반환**(ROUTE: relay). 본문을 응답에 다시 싣지 않는다.
- **opus는 파일에서 재조립**(싼 cat/concat 스크립트)하지, 청크를 다 읽지 않는다.
- 추정: 출력 글자수 ÷ ~3 ≈ 토큰. ~20k 초과 예상이면 쪼갠다. 애매하면 과분할.

## Report 봉투 — sonnet→opus 계약
양자 계약: sonnet은 구조화 리포트를 보내고, **opus는 읽기 프로토콜을 반사적으로 따른다(전체읽기 금지).** 최소 읽기로 최대 결정가치 + 신뢰도.

**① 발사 계약 (opus, 위임 시점):** 위임할 때 작업에 태그 한 번 — **`sonnet-solo`**(사용자가 읽음·되돌릴 수 있음·검토 없이 자동전파 안 됨) vs **`load-bearing`**. 리포트 모양과 기본 ROUTE가 여기서 정해짐.

**② 보내는 쪽 (sonnet)** — 점진 공개로 계층화:
- **L0 헤더(항상):** `ROUTE: relay|judge|respawn|escalate` · `STATUS: done|partial|failed|refused` · 한 줄 `TLDR`.
- **L1 신뢰도(항상):** `coverage` · `confidence: H/M/L + 근거` · `not_seen` · `truncated_due_to` · `assumptions` · `self_falsify`(뒤집힐 조건/최약점).
- **L2 페이로드** (`─── opus: stop here if ROUTE=relay ───` 구분선 아래): 티어별. 각 주장에 `[fact-cited|inference|assumption|base-rate]` 태그 + **VERBATIM 블록**(문자열/숫자/ID/경로/인용/인과사슬은 절대 압축 금지).
- **`signal`(항상):** 필드에 안 들어간 중요한 것 raw로. 없으면 "none". 누락 방지 채널.
- **L3 for_opus (load-bearing만):** `decide` · `pointers` · `open_questions`.

**③ 받는 쪽 (opus)** — L0의 ROUTE를 읽고 **반사적으로 행동, 재추론 금지:**
- `relay` → "완료 + 위치 + L1 플래그"를 1~2줄로 내보내고 멈춤(L2 안 읽음).
- `judge` → 페이로드 읽고 추론.
- `respawn` → 재발사(failed/partial).
- `escalate` → sonnet이 사안 바꿀 걸 찾음 → 읽고 사용자에게 올림.

**두 실패 모드:**
- **과압축(보내기):** sonnet의 진짜 발견이 opus에 도달 못 함. 방어 — `signal` 채널; **발견자가 풍부도를 올린다**(sonnet-solo로 띄웠어도 sonnet이 ROUTE=judge/escalate로 격상 가능); 판단·주의는 절대 caveman 압축 안 함(열거/데이터만 압축).
- **과독(받기):** opus가 매번 전체읽기 = 계약 무효. 방어 — ROUTE는 힌트가 아니라 명령; 구분선이 게으른 길을 올바른 길로 만듦.

**티어 페이로드(L2):**
- **work**(탐색/수집): 열거된 `items`(개수 N 선언) + `file:line` 포인터 + 구조맵; `count_check: N==N`.
- **verify**(기계검증): `pass`(개수만) + `fail`(각각 verbatim: 출처·위치·이유).
- **lens**(의견/자문, deepflow): 고정 순서 `stance · reasons · killer_point · risks · flip_condition · confidence`.

- 런타임이 허용하는 곳(Workflow `schema` 등)이면 **`schema` 강제**해서 누락 필드가 드러나게.

## 팬아웃
- **★ 팬아웃 사전 허락 의무 (사용자 지시 2026-07-20).** 팬아웃(Workflow 포함) 기동 전 **예상 에이전트 총수와 단계별 내역을 사용자에게 보고하고 허락을 받는다.** 기성 워크플로(deep-research 등)는 내부 검증 투표 같은 배수 단계까지 추산해 총수를 제시(실측: deep-research가 claim별 3표 검증으로 66 에이전트까지 팽창). 예외 = 1~2개 단발 조회(보고만). 승인 범위 내 resume는 재허락 불요, 승인 수 초과 예상 시 재허락.
- **① 배치 계획**(몇 개, 각 범위) → **② 병렬 활성** → **③ opus 종합 — load-bearing일 때만**(아니면 ROUTE가 처리, 검토선택 결과는 바로 사용자에게).
- **3티어 + 캡(경험적 시작점, 신뢰도 내 최대):** work(탐색/수집) ~10 / verify(기계검증) ~2 / lens(의견 — deepflow 렌즈, buildflow 적대검토). 하드 천장 아님 — opus가 날카롭게 종합할 수 있는 최대까지.
- **병렬 = 읽기/탐색만, 쓰기는 직렬.** 병렬 쓰기 패턴: 에이전트당 폴더 1개 = `isolation:'worktree'` 1개; 공유파일(타입/설정) + 최종 머지는 opus.
- **병렬은 진짜 독립일 때만(worktree 넘어서도).** 생산자→소비자 의존(한 에이전트 출력이 다른 입력)은 병렬 아님 → 파이프라인하거나 공유입력을 미리 준비. 동시 띄우면 소비자가 빠진 입력을 멋대로 지어낸다.

## 작업 유형별 분담
sonnet = 수집/위치/실행/기계검증; opus = 판단/구성/결정/보기. 분기선 = "verbatim+판단인가, 그냥 가져오기인가".

| 작업 | sonnet (위임) | opus (직접) |
|---|---|---|
| 사람이 읽는 글(자소서·회의록·논문·보고서) | 수집 + 원문 verbatim 추출 + 레이아웃 | 작성(AI 티 제거, 음슴체 보이스) |
| 문서파일 편집(hwpx/pptx/docx) | 스크립트 실행 + rule-4 검증, 보고 | 최종 "납품해도 되나" 판단 |
| 조사/정보수집 | 검색/페치/추출(sonnet 위주) | 종합 + 적대검증 — load-bearing일 때만 |
| 디자인(슬라이드/도판/Figma) | 스캔/익스포트/렌더 | 렌더 보고 미감 판단 |
| 진단/디버깅 | 증상 위치, 로그 수집 | 근본원인 + 수정 결정 |
| 파일 정리/서베이 | 전수 매핑 / 내용 diff | 정리 계획 / 삭제 결정 |

- **Verbatim 본문 함정:** 사용자 글이 한 글자도 바뀌면 안 될 때(자소서/회의록) opus가 원문을 직접 배치; sonnet은 수집만.
- **"봐야 하는" 일:** 디자인 미감/렌더 확인/도판 정합은 이미지를 opus 컨텍스트에 — opus가 직접 본다, sonnet의 "괜찮아 보임" 신뢰 금지.

## 코드작업 분담 (정밀편집=opus, 탐색=sonnet)
- **① sonnet 정찰** — 어느 파일/함수 / 모든 호출처 / 의존·데이터흐름; `file:line` 포인터 + 구조맵 반환. 코드 요약 금지(verbatim 스니펫 아니면 포인터).
- **② opus 정밀** — 가리킨 파일만 Read → 설계, 로직 편집, 리뷰.
- **③ sonnet 검증** — 테스트/린트/빌드 실행, 실패 verbatim 보고; 반복적 기계편집(리네임, 시그니처 전파)도.
- **구현자 완전성:** 코드를 *쓰는* 에이전트는 편집 전 자기 담당 전체(스펙/계약 + 건드릴 기존 파일)를 누락 0으로 읽고 커버리지 보고.
- **opus가 통합·계약 소유** — 청크 간 인터페이스, 통합, 머지는 위임 안 함. **공유 인터페이스 SoT를 먼저** 작성(공유 타입/필드명/enum/에러코드/직렬화/배선), 그 다음 청크별 병렬 초안. 독립 초안 후 화해 = N라운드 churn.
- 구조맵은 재사용(.md 저장)하되, canonical-check 루틴대로 편집 직전 대상 파일을 다시 Read.
