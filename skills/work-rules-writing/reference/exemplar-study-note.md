# Exemplar: a study note where theory and the writer's own understanding mix

Source: https://velog.io/@gagaeun/AWS-IAM (AWS IAM study notes). Chosen by the user on 2026-10-11: "잘 적은건 아니지만, 개인의 의견과 이론이 잘 어우러지고 있음." It is the reference for *how understanding runs through notes*, not for polish. Only short lines are quoted here; read the original for the full shape.

Form: 개조식 with 음슴체 endings (~함, ~음), section headings, English terms kept as they are, code blocks where the subject is code.

What carries the writer's own voice, with the lines that show it:

| Device | Line from the post |
|---|---|
| A question and its answer | 「사용자와 그룹을 생성하는 이유? 이들이 AWS 계정을 사용하도록 허용하기 위해서!」 |
| 「즉,」 restating in their own words | 「SDK는 터미널 내에서 사용하는 것이 아닌 코딩을 통해 애플리케이션 내에 심어두는 것. 즉, 애플리케이션 내에 자체적으로 AWS SDK가 있는 것.」 |
| A comparison to something familiar | 「Access Key ID ~= username」 |
| Emphasis that shows judgement | 「적어도 루트 계정은 무슨 일이 있어도 반드시 보호해야 하고」 |
| A link to something already known | 「예: AWS CLI는 사실상 Boto라는 Python용 AWS SDK에 구축되어 있음.」 |

These lines are the writer's, not the course's. In a journal built from sessions, their equivalent is the user's own questions and the answers they settled on; the devices are a way to place that material, never a licence to invent it.
